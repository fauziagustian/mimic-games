# MIMIC — Sound Battle (web)

An original browser-based sound imitation party game inspired by the *format* of voice party games, not affiliated with Mimic Party/FoliesAPP. No assets from that game are included. Avatars use the CC0 Kenney Mini Characters pack.

## Publish on Netlify with drag and drop

1. Sign in to Netlify, open https://app.netlify.com/drop, and drop `netlify-ready-game.zip` directly. Sign-in is required for Netlify to build this source project and its Function.
2. Let Netlify build the project. `netlify.toml` sets `npm run build:netlify`, publishes `dist/client`, bundles `netlify/functions/game.ts`, and keeps the function at its default `/.netlify/functions/game` URL. The frontend sends API and recording requests directly to that endpoint; there is no `/api/game` redirect.
3. Before sharing the public game URL, open `/admin` and create the one-time owner account with your email and a password of at least 12 characters. The first successful claim becomes Owner; do this yourself before you share the site. Staff accounts use the same account email, then receive Admin or Moderator access from the panel.
4. Start a room and send friends its room code/link. Casual play remains guest-accessible; competitive/creator tools use account login.

Netlify Blobs are initialized by the function on first use. There is no separate database, API key, environment variable, GitHub repository, or manual schema step. The runtime stores the SQLite metadata snapshot and uploaded audio in separate strongly consistent Blob stores; each database update uses an ETag conditional write. The 17 owner-supplied sample clips are bundled into the Function and served through access-checked game routes. The owner confirmed public-use permission on 2026-10-28; speech transcripts remain unverified, so these clips are playable in Party and excluded from Precision word scoring and ranked eligibility.

This is sized for a prototype and small rooms. The current relational adapter reads and conditionally rewrites one SQLite Blob for each mutation, so busy rooms can contend and database traffic grows with the database file. It is not a high-volume production database. Netlify Blobs itself is optimized for frequent reads and infrequent writes. Player recordings are retained; this version has no automatic audio-retention cleanup. Owner/player accounts have no email verification or password-reset flow.

The account page is part of the site. After owner setup, save the password securely; use the Admin panel to create staff accounts after each person has registered at `/login`.


## Run locally

Requires Node 22.13+ (tested with Node 24).

```sh
npm ci
npm run build
npm test
npm run dev
```

Open `http://127.0.0.1:4173/`. The preview serves the production frontend and the same game handler used by `/.netlify/functions/game`. Its strong-consistency Blob adapter persists test rooms and accounts under the ignored `.netlify/local-blobs/` directory. Create the first owner account at `/admin` if you want to test the admin panel. This local address works only on this laptop; sharing with a phone or friend requires an HTTPS deployment.

### Bleach local practice (one player)

Run `npm run dev:bleach` to build and start, then open **http://127.0.0.1:4173/_preview/bleach** in Chrome/Safari on this laptop. Stop with Ctrl+C. Pick one sound or a shuffled four-round session, save your stage name (max 10 characters), choose a character, use headphones and allow the microphone. Each turn plays the reference, shows **Ready → 3 → 2 → 1 → Start**, records automatically, and displays component scores with reference/take replay and retry. New sessions clear the in-memory take history. Switching away from the tab cancels the active turn and releases the microphone.

Four owner-supplied Bleach clips also remain in the separate local practice sandbox. The local-only router `scripts/local-game.mjs` serves these from `private-assets/bleach`; the multiplayer catalog uses the normalized copies in `private-assets/samples`. The shared `audio.js`, `scoring.js`, `scoring-detail.js` and avatar stage power the practice. Party uses relative pitch 60% + rhythm 40% (timbre 60% + rhythm 40% if the reference lacks usable pitch), with the same perfect threshold 98 per active component. Japanese words are not assessed; no ASR model or paid API is used. Scores are browser-local game-rubric results, not competitive/anti-cheat evidence or measured AI accuracy. This is a separate practice sandbox, **not an eight-player room with seven fake players**.

The local **sound visual** uses mirrored waveform bars like a music-player waveform: gray **Contoh**, blue **Kamu**, and a small moving playhead. There are no frequency numbers, axes, pitch tables or technical instructions on the panel. Blue bars come from actual microphone frames; silence remains flat. Both layers keep the same raw-time and amplitude scale. The visual is a short-window RMS amplitude envelope, **not a pitch curve or similarity score**; Party's pitch/rhythm scoring remains unchanged behind the scenes. The old `pitch-guide.js`/`createPitchGuide` filename/API is retained for compatibility. Results keep both waveforms; total score/reaction is prominent, with technical breakdown behind **Rincian skor** and explanatory notes behind **Cara main & info latihan**. This is wired into local practice only, not the public multiplayer arena.

The practice page and its WAV routes exist only in the local Node preview. The regular game at `/create-match` now has playable **Anime → Bleach**, **Meme → Meme Global**, and **Meme → Meme Indonesia** collections. Custom rooms still require all 2–8 seats to be filled; solo queues require eight players. `127.0.0.1` is laptop-only; real phone multiplayer requires a reachable HTTPS deployment.

Practice now shows a cumulative score card after each completed round, with **+this-round points**, and a collapsed round-by-round running total. A retry replaces that round's score; starting a new session resets the total. It remains explicitly one-player practice, not a simulated multiplayer ranking.

### In-match score cards

After every remaining player finishes their turn and playback, the main arena shows avatar cards ranked by **cumulative match total**, highest first. Each card shows rank, stage name, total points and **+points this round**. The server's 12-second inter-round timer then starts the next round; the last round keeps the final standings visible. For example, 80 + 75 gives **155 total points** (not an average or a score capped at 100).

The existing server commits each round score once; clients only display its total. Rank sorting never mutates the roster/turn order. Equal totals share a rank (1, 1, 3); tied winners are labelled jointly. Departed players' retained totals appear separately under **Players who left**, not among active winners. A timed-out take adds 0. This has no connection to the global `/leaderboard`, which remains Coming soon.

Automated coverage includes three concurrent clients across two rounds, cumulative reordering, duplicate polls, late reconnect-style reads, ties, missing/zero scores, departures, safe names, Indonesian/English markup and local retry/reset. These are isolated Worker/D1 tests and DOM doubles; rendered layout, live microphone and physical Android/iPhone testing are not claimed.

## Product

- Gameplay is split into dedicated URLs: `/` is a lightweight menu; `/choose-character` edits identity/avatar; `/create-match` configures category/language/profile and an optional collapsed sound library; `/matching` joins by invite code and `/matching?room=CODE` is the lobby; `/room/CODE` is the focused recording/playback arena. Netlify rewrites serve deep links, and same-document navigation keeps the armed microphone across lobby → arena. Back/forward, old `/?room=CODE` invitations, and sessionStorage resume are supported. A URL/code alone is not room authentication.
- `/leaderboard` is **Coming soon** only: no seasons, rankings, filters, or submission table. Ranked selection is absent from the main create flow; both Party and Precision are casual matches for now. Existing ranked data, moderation tools and backend endpoints are preserved, not deleted.
- **Custom**: host selects 2–8 players; every slot must be filled and every player Ready before the host can start. **Solo matchmaking**: automatically groups independently joining players with identical category/language/profile and catalog/rule snapshots into exactly 8-player rooms. Starts automatically only when all eight are Ready; no bots and no partial-room starts. Solo uses random sound pools, not invite-code joins or manually picked clips. Guest casual play does not require login; the old one-player practice creation option is removed.
- Stage names require an explicit **Save name** on `/choose-character`, with a 10-character limit in the field and server. Unsaved/invalid names block Continue. Saves update the 3D label, 2D fallback, all room clients and stored membership. Own name/avatar edits are allowed in the lobby, locked during battle. Existing long names must be edited before starting.
- Server-owned shared clock and room state, polled approximately every second. Ready arms a disabled microphone stream; actual recording is only during the player's own recording window. No second take in a round. Keep the tab foregrounded.
- **Dropouts:** explicit Leave removes the active seat immediately. Authenticated polling renews a server receipt-time heartbeat, stored at most once per 5 seconds; a seat expires at 30 seconds from its stored heartbeat (roughly 25–31 seconds after the last successful poll, including the next remaining client's poll). All room requests reconcile expired players atomically. During battle, 8 → 7 continues without refilling the lobby; departing active players are skipped, host ownership transfers to the first remaining player, and recorded scores/history are preserved. One remaining player can finish the rounds; no remaining players closes the active match when it is next accessed. Finished standings are frozen. Lobby dropouts free their seats, but full capacity and all-Ready are still required to start. Solo joins also reclaim expired queue seats without old clients polling.
- Brief reconnects/reloads retain membership while the lease is valid. Once evicted, the old token cannot resume or upload; mid-battle replacements are disallowed. Presence uses the existing room JSON and compare-and-swap transaction, not client-supplied timestamps or a fragile unload event. Heartbeat-only changes do not bump the visible revision or reset UI inputs. Polls time out after 8 seconds; returning online/foreground retries. On phones, a suspended/backgrounded browser can stop polling and be removed too: keep the game open and the screen awake. No scheduled background sweeper is claimed.
- Shuffle without repeats until the chosen category/language pool is exhausted. All players get the same round sound. Rules and reference audio profiles are snapshotted at room creation.
- Dynamic themes have two levels: **Anime → Bleach**, **Meme → Meme Global / Meme Indonesia / Meme Lucu**, or new roots/children created by Owner/Admin. Create Match has separate root/subcategory controls. A root selection aggregates its direct sounds and active children; a leaf selects only that leaf. Eligibility is enforced server-side for custom pools, solo queues, UGC visibility/submission and old ranked creation endpoints. Disabling a parent hides descendants from new selection. Existing room labels/pools stay snapshotted. Category saves use atomic structure/revision checks to prevent cycles and stale overwrites; no schema migration is needed for the parent metadata.
- The 17 owner-supplied samples (4 Bleach, 9 global memes, 4 Indonesian memes) are active for casual Party matches and not ranked. Original MP3 files in Downloads remain unchanged. Three long clips were cut to 14.95 seconds, and all bundled WAVs pass the 0.25–15-second format and signal checks. The owner confirmed public-use permission. Speech text is an unverified play hint, not an exact answer key; these clips are excluded from Precision until an admin listens and confirms each transcript. The server-only audio bundle is access-checked per request and admin disabling revokes future access. The sample seed preserves subsequent admin edits. See `private-assets/sample-collections.json` and [ADMIN-GUIDE.md](ADMIN-GUIDE.md).
- Players perform in lobby order. Each turn: reference playback → Ready → 3 → 2 → 1 → Start/record → score/shared playback → next player. After all players, next round or room standings. Each preparation cue is one second; Start is the first recording second. Only the active player's new take is accepted by the server. Timeout assigns zero (30-second post-record upload window for Party, 140 seconds for Precision). There is no live voice streaming or peer-to-peer/TURN dependency. Running legacy matches keep their old protocol; newly started matches use sequential turns.
- Speech: Party uses relative pitch contour 60%, rhythm 40%. Precision defaults to pitch 30%, words 35%, timbre 20%, rhythm 15%; adjustable by admin. New rooms use `mimic-v2`: non-verbal effects use timbre 60% + rhythm 40% with no transcript or periodic-pitch requirement. Insufficient reference pitch excludes that weight and normalizes the others; insufficient player pitch gets zero pitch, not zero on every component. Existing rooms retain their scoring snapshot.
- Read [SCORING.md](SCORING.md) for exact formulas, perfect-score rules, transcription/pitch/timbre limitations and validation status. There is no separate musical-notation component and no measured real-voice accuracy percentage. Software test pass rates are not model accuracy.
- Browser Whisper Tiny multilingual (default) or optional Base handles Precision speech transcription on each player device. No paid transcription API or API key. Models/libraries download from jsDelivr/Hugging Face; audio is not sent to an ASR provider. Base is larger, not proven more accurate on this game's sounds, and needs device testing. Server computes acoustic features and scores. Failed take transcription uploads the audio with words=0 and a visible warning; it does not reallocate the missing word weight. Initial model preparation failures still require retry or a Party room. Live transcript input remains advisory/untrusted for competitive ranking.
- **Scoring Lab** at `/admin?tab=scoring`: Owner/Admin selects a catalog reference and uploads a mimic test, optionally transcribes locally, then inspects server-calculated components, effective weights, reference/heard words, source labels, and silence/clipping/pitch warnings. Editing recognized words labels them manual. Lab audio is not retained and no match/leaderboard scores change; 60 tests/hour per admin, with a database usage counter. Sound editing includes a local ASR draft assistant; humans must correct reference words before saving. Reference silence/DC-only uploads are rejected. Missing pitch alone does not invalidate a non-verbal reference.
- Preserved ranked backend (not offered in the new player flow): requires ChatGPT sign-in and Precision. Recordings stay pending until an admin hears them and supplies a verified transcript. Server recomputes the final score. Admin cannot review their own attempt. This is **not fully automated anti-cheat**, and modified reference playback can require human detection.
- Preserved ranking formula: category rating = average best approved score per distinct sound; overall rating = average of played category ratings. This is not ELO and does not normalize for category difficulty or coverage. Rule revisions and earlier ranking records are retained; the public leaderboard currently shows only Coming soon.
- Admin: audio uploads/metadata/permissions, category and language activation, rules and reaction text/audio, score moderation and activity log. Disable records instead of destructive deletion.
- Community UGC: browse approved sounds at `/community`, submit owned/licensed audio with creator credit and transcript, track review notes, and withdraw submissions. Sign-in is required to submit, not to browse or play casually. Indonesian/English UI; all active sound languages and categories are loaded from the admin catalog.
- Six original synthetic starter clips, plus 17 owner-supplied Bleach and meme samples; 14 selectable sound languages. The supplied samples are casual Party content until their speech transcripts are reviewed.

## Storage and access

### Admin Control Center

The `/admin` panel now opens on a real-data dashboard and includes dynamic website content, operational switches, room monitoring/closure, protected owner-managed Admin/Moderator roles, configuration version history, and a metadata-only JSON export. Existing sound/category/language/rule/UGC/ranked moderation editors are retained. All staff permissions are enforced on the server. Website and operation values are durable records in the existing `config` table; no schema migration is needed. Published content uses escaped plain text, never arbitrary HTML or JavaScript. Read [ADMIN-GUIDE.md](ADMIN-GUIDE.md) for access, maintenance behavior, version recovery and verification boundaries.

Custom casual hosts can choose a 1–50 sound pool within the selected category/language/duration limits. The server snapshots and shuffles that pool for all players. Ranked games stay random, and operators can disable new custom pools without changing running matches.

### 3D avatars

Choose one of 12 Kenney avatars on the dedicated `/choose-character` page. The lobby links back to that page for edits. The server validates an allowlisted avatar ID, stores it in the room, and synchronizes it to other players. Choices lock when a match starts. Existing rooms without an avatar use the default character. The arena keeps a compact 2D/3D stage without the character picker; the current turn/countdown and scoring take priority. There is no arbitrary model upload endpoint.

Three.js is lazy-loaded for the decorative living-room stage. One canvas survives room UI refreshes. Independent cloned skeletons play idle, recording/replay gestures, nod/shake reactions, and a perfect-score/winner jump animation. Reactions follow the authoritative room state and server-adjusted clock; the player keeps the same seat throughout the match. These are body animations, **not facial animation or lip-sync**. The original primitive-geometry room does not use the supplied props whose public-use licenses are still unconfirmed.

The **2D / 3D** button stores a device-local view preference. Save-Data defaults to 2D. Reduced-motion makes avatar poses static and disables confetti. WebGL/import/model failure falls back to thumbnails without blocking game controls, microphone recording or scoring. Rendering is capped at 30 FPS and device pixel ratio 1.5, and pauses when offscreen or the tab is hidden. Only characters present in the scene are requested; all 12 GLBs combined are approximately 3 MB. GPU resources are released on disabling 3D/page exit.

Files: `client/stage-3d.js`, `client/stage-scene.js`, `public/avatars.js`, `public/avatar-ui.js`, `public/avatars.css`, and `public/models/kenney/`. The build bundles Three.js and includes `.glb`/PNG assets with their correct MIME types. To re-import the same pack from an authorized local ZIP: `node scripts/import-characters.mjs /path/to/kenney_mini-characters.zip`. Preserve the shared `Textures/colormap.png` and `License.txt`. Credits and asset decisions are in `ASSETS.md`.

### Community sounds (UGC)

1. A signed-in creator uploads a 0.25–15 second clip (up to 8 MB before browser conversion to mono PCM16/16 kHz WAV). The server validates the actual WAV, bounds the request, rejects silence/DC-only input and computes the reference profile. Metadata includes a public creator name, speech/non-verbal type, exact transcript (required for speech only), category, language, source, permission details and explicit publication consent. Moderators can verify the type before approval. No scraping or automatic licensing of viral/influencer audio is included.
2. Netlify Blobs stores the audio and the strongly consistent SQLite metadata snapshot. Pending, rejected and withdrawn audio is available only to its creator and admins. Creator IDs, acoustic profiles and private review notes are not in the public community response.
3. Admin Studio → **UGC moderation** lists the oldest pending submissions first. Listen and verify transcript, permissions and content safety, then approve or reject (with a required reason). Approval atomically creates a casual-only catalog sound. A separate Sound library setting enables ranked eligibility; UGC approval never grants leaderboard points. Only sounds within a room's recording limit are eligible for its shuffle.
4. Public community browsing has category/language filters and pagination. Approved UGC enters the existing server-owned multiplayer selection. Inactive sounds/categories/languages are omitted and their UGC audio is no longer publicly served.
5. Creators can withdraw their own submissions. Withdrawal blocks new public audio requests and selection in new rooms, cannot be reversed by a stale admin edit, and does not erase copies already loaded by players. Files and moderation records remain stored; automatic deletion is not implemented. UGC audio replacement is disallowed in admin editing to preserve creator attribution; submit a new clip instead.

Server-enforced limits: 5 submissions per rolling 24 hours, at most 10 pending. Atomic quota checks prevent concurrent bypass; request IDs make retries idempotent. Moderation and withdrawal are transactional, and losing upload contenders remove only their own unreferenced Blob. Public audio responses use `private, no-store` so every new request rechecks visibility. Review is manual, not automated abuse/copyright detection. This release has no creator monetization, sound packs, comments, or public reporting queue.

The Netlify function is request-scoped at `netlify/functions/game.ts`; helper modules stay in `server/`. All game API requests use its standard default route, `/.netlify/functions/game`, with the API route carried in a query parameter. Room tokens are scoped to a room and stored hashed in the metadata snapshot; clients keep their token in sessionStorage for reload recovery. Rooms expire after two hours. Uploaded library clips are public content; player recordings are served to room members during the room lifetime and to authorized ranked reviewers. Stored recordings are retained; there is no scheduled automatic deletion. Do not use for sensitive recordings.

Schema is in `db/schema.ts`; generated schema-only migrations are in `drizzle/`. Use `npm run db:generate` after schema changes. Source assets are in `public/`, request handlers and Blob helpers in `server/`, the Netlify entry point in `netlify/functions/game.ts`, and deployment routing/build settings in `netlify.toml`. `npm run build` creates the static client in `dist/client` plus generated private-data/schema inputs for function packaging. The old `build:worker` and local preview scripts are retained for local regression checks; the Netlify deployment does not run a persistent Worker.
